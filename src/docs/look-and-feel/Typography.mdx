## One property drives every size

`src/styles/base.scss` sets the size of every element on the page in two rules:

```css
body {
	font-size: $font-size;
	line-height: 1.6;
}

:where(body *) {
	font-size: $font-size;
}
```

`$font-size` is the alias for the custom property `--font-size`, which starts at `1.0625rem` (17px)
on `:root`. So a class changes the type size by setting the **property**, never `font-size`:

```css
.badge {
	--font-size: 0.8125rem;
}
```

> **Why not just write `font-size`?** Because `:where(body *)` re-applies `font-size: var(--font-size)`
> to every element inside the badge as well. A plain `font-size` on `.badge` would be undone on its
> children, which would snap back to the root's 17px. Setting `--font-size` instead lets the value
> inherit, and the children follow.

## Size and meaning are separate choices

`h1` through `h6` say what a heading *is*: the document outline, the thing a screen reader announces
and a search engine reads. The `.h1`–`.h6` classes say what it *looks like*. Keeping them apart means
a page can open with a real `h1` that is visually modest, or give an `h3` the size the layout needs.

The split is literal in `base.scss`. The tag selectors set only the shared look:

```css
h1,
h2,
h3,
h4,
h5,
h6,
.h1,
.h2,
.h3,
.h4,
.h5,
.h6,
.title {
	font-family: var(--font-display, var(--font-sans, system-ui, sans-serif));
	font-weight: $weight-semibold;
	letter-spacing: $tracking-tight;
}
```

No size in there. A bare `<h1>` gets the display font, the semibold weight and the tight tracking —
and body size, because nothing set its `--font-size`. The size arrives only with a class.

### `Title` picks both

`src/components/basics/Title.tsx` turns that into two props:

```tsx
const Title = ({
	element,
	size = 2,
	className,
	value,
	href,
	linkClassName,
	id,
}: TitleProps) => {
	const Element = (element || `h${size}`) as React.ElementType;
	const content = value && parse(value);

	return (
		<Element className={classNames('title', `is-${size}`, className)} id={id}>
			{href ? (
				<Interactive url={href} className={linkClassName}>
					{content}
				</Interactive>
			) : (
				content
			)}
		</Element>
	);
};
```

- `size` (1–6, default 2) picks the visual role by writing the class `is-1` … `is-6`.
- `element` picks the tag. Omit it and the tag follows the size — `size={3}` renders an `h3`.

So `size={2} element="h1"` is a page's real first heading at the h2 size, and `element="p"` gives a
paragraph the heading look without polluting the outline.

`.title.is-1` … `.title.is-6` are not a second scale. They are declared on the same rule as
`.h1`–`.h6` in `src/styles/base.scss`, so a `Title` and a bare `.h1` resolve to the same size *and*
the same line-height:

```css
.h1,
.title.is-1 {
	--font-size: 2rem;
	line-height: 1.1;
	// …
}
```

	<Sample label="$tracking-wider · 0.08em — small uppercase labels"><span style={{ fontSize: '0.875rem', fontWeight: 500, textTransform: 'uppercase', letterSpacing: '0.08em' }}>Aankondiging</span></Sample>
</Box>

Large text needs *less* spacing than small text, which is why the only automatic one is the negative
tracking on headings. The wider value is for the opposite case — uppercase text at 14px, where the
letters would otherwise crowd. `HeadingGroup` does exactly that with its tagline:

```css
.heading-group-tagline {
	--font-size: 0.875rem;
	font-weight: $weight-medium;
	text-transform: uppercase;
	letter-spacing: $tracking-wider;
	color: $primary-text;
}
```

## Line length

`$measure` is `60ch` — sixty zero-widths of the current font, so it scales with the type size rather
than being a fixed pixel width. It caps a column of running text at a comfortable line, somewhere
around 65–75 characters in practice.

	<div style={{ maxInlineSize: '60ch', paddingBlock: '0.9rem', paddingInlineStart: '0.9rem', borderInlineStart: '0.1875rem solid rgba(128, 128, 128, 0.45)' }}>Deze kolom is precies 60ch breed. One stylesheet uses it today — `HeadingGroup.scss`, on the intro paragraph under a heading:

```css
.heading-group-intro {
	color: $color-secondary;
	max-inline-size: $measure;
}
```

`max-inline-size` rather than `max-width`: see [Spacing](?path=/docs/look-feel-spacing--docs) for what
the logical properties buy.

## The typefaces

Two, loaded by `next/font` in `src/app/layout.tsx` and exposed as custom properties:

```tsx
const sans = Manrope({
	subsets: ['latin'],
	variable: '--font-sans',
	display: 'swap',
});

const displayFont = Poppins({
	subsets: ['latin'],
	weight: ['500', '600', '700'],
	variable: '--font-display',
	display: 'swap',
});
```

`body` uses `var(--font-sans, system-ui, sans-serif)`; headings use `--font-display` and fall back to
`--font-sans`. Poppins ships only the three weights listed, which is why 400 never appears in a
heading.

Storybook loads neither, and its documentation pages impose their own UI font on top. So the samples
above are accurate about size, weight, line-height and letter-spacing, and wrong about the
letterforms. To see Manrope and Poppins, run `npm run dev` and open the site.

## Which class for which job?

| The job | Use |
| --- | --- |
| A heading in content | `Title` with `size`, and `element` when the outline needs a different tag |
| Heading styling on something that is not a heading | `.h1` … `.h6` |
| Running text | nothing — `body` is already 1.0625rem |
| A lead paragraph under a heading | `HeadingGroup`'s `intro` prop, or `.body-large` |
| Fine print, helper text under a field | `.body-small` |
| An image caption, a timestamp | `.caption` |
| A small uppercase label | `$tracking-wider` with `$weight-medium` at `0.875rem` |
| One component that needs its own size | `--font-size` in that component's stylesheet |
| A block of rich text | `Content`, which sets `1rem` and takes `size="small"` / `size="large"` |
